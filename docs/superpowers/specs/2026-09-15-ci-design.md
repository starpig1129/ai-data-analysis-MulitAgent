# CI Design

- **Date:** 2026-09-15
- **Status:** Approved design, pending implementation
- **Scope:** First GitHub Actions CI for DATAGEN (lint, format, type check, tests,
  dependency audit, CodeQL, Dependabot) plus the one-time cleanup that lets it
  pass on day one.

## Goals

1. Every pull request, including ones from forks, gets an automatic signal on
   lint, formatting, type errors and tests before a maintainer looks at it.
2. `main` cannot receive changes that fail those checks (admins may bypass).
3. Dependency and workflow versions stay current and audited without manual
   effort.
4. CI results are reproducible: the same commit gives the same result.

## Non-goals

- Docstring enforcement (ruff `D` rules, ~265 violations today). Revisit later.
- `mypy --strict`.
- Packaging changes: no `[project]` table; the app keeps installing from
  `requirements.txt`.
- Live LLM or MCP calls in CI. CI uses no secrets.
- Release, Docker or deployment automation.

## Baseline (main @ fe9bd2b)

| Check | Result |
|-------|--------|
| `ruff check` (default rules) | 51 errors: 32 F401, 17 E402, 1 F541, 1 F821 |
| `ruff format --check` | 44 of 51 files would be reformatted |
| `E,F,W,I,B,UP` after format + safe autofix | 74 remaining: 40 E501, 16 F401, 15 E402, 1 F821, 2 UP |
| `pytest tests` | 8 passed |
| mypy 2.3.1 (`python_version = "3.10"`, not strict) | 17 errors in 9 files; all annotation-level except the F821 below |
| Import each `src` module in a fresh interpreter | 3 of 47 fail with a circular `ImportError` |

The F821 is a real bug: `src/core/mcp_manager.py:271` falls back to
`sys.stderr` when `logs/mcp_servers.log` cannot be opened, but the module never
imports `sys`, so the fallback path raises `NameError` (swallowed by
`connect()`, which then fails the MCP connection).

The circular import is a latent bug: `src/core/__init__.py` eagerly imports
every core module, including `workflow` → `agents.factory` → every agent. Any
import of a small core module (e.g. `src.core.schemas` from `code_agent`)
therefore loads the whole agent graph, so importing `src.agents.code_agent`,
`src.agents.process_agent` or `src.agents.factory` first fails. The app only
avoids it because `main.py` enters through `src.system`.

`requirements.txt` has `mcp>=1.0.0`, which now resolves to mcp 2.2.0. mcp 2.0
replaced the `ClientSession` + `stdio_client` layering that
`src/core/mcp_manager.py` uses, so fresh installs currently get an
incompatible SDK (the maintainer's working env has mcp 1.27.0).

## Decisions

| Topic | Decision |
|-------|----------|
| Strictness | Enforce lint, format and mypy from day one after a one-time cleanup (no open PRs to conflict with). |
| Python versions | Test on 3.10 (README minimum) and 3.13 (newest). Lint and mypy run once, on 3.13. |
| Extra checks | Dependabot, pip-audit, CodeQL, mypy. |
| Layout | Separate workflow files per purpose (option A). |
| Unpinned deps | Pin `langchain-crw==0.5.0` and `mcp==1.27.2` (latest 1.x; see the mcp 2.0 note above). Migrating to mcp 2.x is a separate task. |
| Circular import | Empty `src/core/__init__.py` (drop its eager re-exports; nothing in the repo uses them) rather than making them lazy. |
| Merge gate | Branch protection on `main`: required checks, admins may bypass, no required review count. |

## 1. Tool configuration

New `pyproject.toml` containing tool settings only:

- **ruff**
  - `target-version = "py310"`, default `line-length` (88).
  - `select = ["E", "F", "W", "I", "B", "UP"]`.
  - `ignore = ["E501"]`: line length is owned by the formatter.
  - No `per-file-ignores` initially. Tests drop their `sys.path.insert` hacks
    once pytest's `pythonpath` is set, which removes their `E402`s. Add a
    `tests/*` `E402` ignore only if a test still needs import-order tricks
    after that.
- **mypy**
  - `python_version = "3.10"`, `ignore_missing_imports = true`, not strict.
  - Checks `src/` and `tests/`.
  - Fallback if the first CI run reports too many errors to fix in this PR:
    `[[tool.mypy.overrides]]` with `ignore_errors = true` for the worst modules,
    each marked with a comment as pending cleanup.
- **pytest**
  - `testpaths = ["tests"]`, `pythonpath = ["."]` so tests can drop their
    `sys.path.insert` hacks.
  - `timeout = 60` via `pytest-timeout`, so a hung test fails instead of
    stalling the job.

New `requirements-dev.txt` pins the tool versions: `ruff==0.15.16`,
`mypy==2.3.1`, `pytest==9.1.1`, `pytest-timeout==2.4.0`, `pip-audit==2.10.1`.
Ruff stays on 0.15.16 (the maintainer's installed version) so local and CI
formatting match exactly; Dependabot proposes the 0.16 upgrade separately.

New `.git-blame-ignore-revs` lists the SHA of the mechanical formatting commit
so GitHub blame skips it.

## 2. Workflows

Shared rules for every workflow:

- Third-party actions pinned to full commit SHAs with a version comment;
  Dependabot updates them.
- Top-level `permissions: contents: read`; jobs widen only what they need.
- Every job sets `timeout-minutes`.
- No secrets, so fork PRs run the same checks.
- Dependencies installed with `astral-sh/setup-uv` with caching enabled.

### `ci.yml`

Triggers: `pull_request`, `push` to `main`, `workflow_dispatch`. A
`concurrency` group per ref cancels superseded PR runs.

| Job | Python | Steps |
|-----|--------|-------|
| `lint` | 3.13 | install deps + dev deps; `ruff check`; `ruff format --check`; `mypy` |
| `test` | matrix 3.10, 3.13 (`fail-fast: false`) | install deps + dev deps; `pytest` |

### `dependency-audit.yml`

Triggers: `pull_request`, `push` to `main`, weekly `schedule`,
`workflow_dispatch`.

The job always runs so it can be a required check (a workflow-level `paths`
filter would leave unrelated PRs waiting forever on a required check that never
starts). Its first step checks whether the change touches `requirements*.txt`:

- no dependency change on a PR: exit successfully;
- dependency change, push to `main`, or scheduled run: run
  `pip-audit -r requirements.txt` and fail on any known vulnerability.

Unrelated PRs therefore never turn red because of a newly published upstream
CVE; the weekly run surfaces those instead.

### `codeql.yml`

GitHub's standard CodeQL setup for `python` and `actions` (the latter scans the
workflow files themselves). Triggers: `pull_request`, `push` to `main`, weekly
`schedule`. Not a required check initially, to observe false positives first.

### `.github/dependabot.yml`

- `pip` ecosystem (`requirements.txt`, `requirements-dev.txt`), weekly.
  LangChain packages (`langchain*`, `langgraph*`) are grouped so they upgrade
  together. Major updates of `mcp` are ignored until the mcp 2.x migration.
- `github-actions` ecosystem, weekly.
- At most 5 open Dependabot PRs per ecosystem.

### Branch protection on `main`

Required status checks: `lint`, `test (3.10)`, `test (3.13)`,
`dependency-audit`. Admins may bypass. No required review count. Configured
with `gh api` after the CI PR merges, with explicit maintainer confirmation.

## 3. Cleanup and rollout

One PR from branch `ci/setup`, as separate commits in this order:

1. `docs`: this spec and the implementation plan.
2. `chore`: `pyproject.toml`, `requirements-dev.txt`, pin `langchain-crw` and
   `mcp`.
3. `style`: `ruff format` plus safe autofixes only. Mechanical, no logic change.
4. `fix`: the missing `import sys` in `src/core/mcp_manager.py` (regression
   test written and seen failing first).
5. `fix`: break the circular import by emptying `src/core/__init__.py`
   (the fresh-interpreter import smoke test is the regression test).
6. `refactor`: remaining lint issues.
7. `fix`: mypy errors (all 16 remaining are annotation-level, so no
   `ignore_errors` overrides are expected).
8. `ci`: the four workflow files and `dependabot.yml`.
9. `docs`: `.git-blame-ignore-revs` with the SHA of commit 3, and a short
   README section on running the checks locally.

**The PR must be merged with "Create a merge commit".** Squash or rebase
merging rewrites commit 3's SHA and breaks `.git-blame-ignore-revs`.

### Guarding against cleanup regressions

- Unused imports in `__init__.py` that act as re-exports are made explicit
  (`__all__` or `import x as x`) instead of deleted.
- New `tests/test_imports.py` imports every module under `src/` in its own
  fresh interpreter (47 modules, about 25 s), so a wrongly removed import or
  an order-dependent circular import fails CI even though test coverage is
  low.
- mypy fixes add or correct annotations only; any real bug found is fixed in
  its own commit with the reason stated.

## Verification

1. The `ci/setup` PR runs its own new workflows; iterate until all required
   checks pass. Record the mypy error count from the first run.
2. Maintainer reviews and merges with a merge commit.
3. After merge: confirm `ci.yml`, `dependency-audit.yml` and `codeql.yml` run on
   `main`, and Dependabot is enabled.
4. Configure branch protection (after confirmation) and verify with
   `gh api repos/{owner}/{repo}/branches/main/protection`.

## Risks

- **Local environment drift.** The mypy baseline and import checks were
  measured in the maintainer's `datagen` env plus a few extra wheels, whose
  package versions are newer than `requirements.txt`. CI installs the exact
  pins and may report a few different mypy errors; the per-module override
  remains the fallback. (On the dev machine, IPv6 to PyPI is unreachable, so
  `pip`/`uv` stall; `curl -4` works.)
- **mcp pinned to 1.x.** Security fixes that ship only in mcp 2.x would need
  the migration; pip-audit's weekly run will surface that.
- **Import side effects.** `src/config.py` calls `load_dotenv()` and reads
  `agent_models.yaml` at import time. CI has no `.env`, so `CONFIG_DIRECTORY`
  defaults to the tracked `config/`. Locally, a parent directory's `.env` can
  point elsewhere (seen when running from a git worktree); run tests with
  `CONFIG_DIRECTORY=config` in that case.
- **Upstream CVEs.** A new advisory can fail the weekly audit or a dependency
  PR; that is the intended signal, handled by a Dependabot or manual bump.
